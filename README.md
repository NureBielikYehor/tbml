# StepFund

`tbml` — технічна назва репозиторію за назвою дисципліни; бренд платформи — **StepFund**.

Краудфандинг із прогнозом успішності та поетапною виплатою коштів після голосування вкладників. Тема №18 з дисципліни «Технологія блокчейн та машинне навчання».

Команда: **Бєлік Єгор і Глоба Максим, ПЗПІ-23-6**. Працюємо спільно над усіма частинами. Репозиторій: [NureBielikYehor/tbml](https://github.com/NureBielikYehor/tbml).

## Реалізовано

- Три типи Solidity-контрактів: фабрика, кампанія з етапами/голосуванням/поверненням, реєстр прогнозів і моделей.
- Реальний Python ML: частка успіху в категорії як baseline, LogisticRegression і HistGradientBoosting із числовими ознаками та справжніми короткими описами.
- Node/Express oracle: незмінні входи → inference → аудит → транзакція дозволеної адреси.
- Український інтерфейс: створення, прогноз, внески, звіти, голосування, транші й повернення.
- Виконаний Jupyter EDA з 8 графіками, порівняння/абляції/калібрування ML, контрактні та Python-тести, наскрізна демонстрація.

Це **локальний навчальний демонстратор** на chainId 31337. Він використовує розблоковані тестові акаунти Hardhat. Зовнішнє розгортання, приватні гаманці користувачів, IPFS і фінальний оформлений звіт не є частиною цього запуску.

## Швидкий запуск у підготовленому workspace

```bash
npm run dev
```

Відкрити **http://127.0.0.1:3000**. Команда компілює контракти, запускає нову локальну мережу, деплоїть factory/registry та запускає API з Python worker. Порти 3000 і 8545 мають бути вільними. Для зупинки — Ctrl+C. Перезапуск створює новий in-memory blockchain, тому кампанії попереднього запуску в новій мережі відсутні.

У правому верхньому куті можна перемикати навчальні ролі: автор, вкладник A, вкладник B, адміністратор. Для голосування є кнопка пришвидшення часу **лише в локальному демо**. Кошти справжньої мережі не використовуються.

## Відтворення з нового клону

Потрібні Node.js 24+, Python 3.11+ (перевірено на 3.12), мережа для початкового завантаження залежностей/даних. Використовуйте наявний Python відповідної версії замість `python3.12`, якщо він має іншу команду.

```bash
npm ci
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python scripts/download_kickstarter.py
.venv/bin/python scripts/download_descriptions.py
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 .venv/bin/python -m ml.train
.venv/bin/python scripts/audit_kickstarter.py
.venv/bin/python scripts/create_eda.py
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 .venv/bin/python -m ml.experiments
npm run dev
```

Команди отримання даних призначені для нового клону; якщо CSV вже є, повторне завантаження пропустіть. На Windows синтаксис шляху Python і змінних середовища відрізняється. Встановлені залежності, сирі дані, модельні файли й локальний стан виключені з Git.

Параметри за замовчуванням працюють без `.env`. Для зміни порту/інтерпретатора скопіюйте `.env.example` у `.env`. Адреси контрактів генеруються під час деплою в `data/local/deployment.json`.

## Перевірки і сценарій захисту

```bash
npm test
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
```

Коли `npm run dev` працює, в іншому терміналі:

```bash
npm run test:integration
npm run demo
```

`demo` реально створює кампанію, отримує прогноз через API/оракул, збирає 10 ETH від двох тестових адрес, схвалює та виплачує перший транш 4 ETH, відхиляє другий етап і перевіряє повернення **3.6 та 2.4 ETH**, залишок контракту **0**. Хеші транзакцій, gas і локальний час підтвердження записуються в `reports/blockchain/demo.json`.

Інтеграційні тести створюють окремі тестові чернетки й перевіряють відхилення чужого Origin, некоректних запитів, підміненого контенту та невідповідних параметрів. Запускайте їх у власній локальній навчальній мережі.

Для роздільного запуску доступні `npm run chain`, `npm run deploy`, `npm start`.

## Перевірені результати ML

Основний CSV має 378661 кампанію; після вибору successful/failed — 331675. Описи приєднано за ID для 165434 із них. Усі три методи порівнюються на цій самій підмножині: train 113038, validation 23069, test 24845; 4482 записи на часових межах вилучено, щоб не навчатися на ще невідомих результатах.

| Метод | F1 test | ROC-AUC test | Brier test |
|---|---:|---:|---:|
| Частка успіху в категорії | 0.7302 | 0.7297 | 0.2213 |
| LogisticRegression | **0.7631** | **0.8049** | **0.1912** |
| Histogram gradient boosting | 0.7542 | 0.7917 | 0.1978 |

Модель обрана за validation ROC-AUC. Значення зберігаються в `reports/ml/metrics.json`; абляції й умовний bootstrap — в `reports/ml/experiments.json`. Після нового навчання результати потрібно перевірити заново. Поле `pr_auc` у JSON означає average precision (AP), обчислену `average_precision_score`, а не трапеційну площу під PR-кривою.

**Обмеження даних:** Web Robots надає короткий `blurb`, а не повну історію. Snapshot не доводить незмінності тексту з моменту запуску; покриття класів нерівномірне, явна ліцензія повторного використання знімка не знайдена. Сирі тексти не публікуємо в Git. Модель дає ретроспективний прогноз збору на Kickstarter, не гарантію виконання й не перевірену точність для нових криптокампаній. Бюджет у фіатній валюті для ML задається окремо від тестового ETH, без автоматичного курсу.
